# PadungGo Backend

Python 3.11+ (3.12 in production) · Django 5.2 · DRF · Supabase PostgreSQL/PostGIS.

Two database modes:

- **lite** (`PADUNGGO_DB_ENGINE=sqlite`): local development and tests. No GDAL/PostGIS needed.
- **postgis**: production on Render. The Docker image installs GDAL/GEOS/PROJ.

## Local setup (Windows PowerShell)

These commands call the virtual environment's Python directly, so they work
even when PowerShell's execution policy blocks `Activate.ps1`.

```powershell
cd backend
py -3.12 -m venv .venv            # or py -3.11
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env       # then set DJANGO_SECRET_KEY in .env
.\.venv\Scripts\python.exe manage.py migrate
.\.venv\Scripts\python.exe manage.py createsuperuser  # for /admin
.\.venv\Scripts\python.exe -m pytest                  # run the test suite
.\.venv\Scripts\python.exe manage.py runserver        # http://127.0.0.1:8000/health
```

Migration check, as CI runs it (PowerShell):

```powershell
$env:PADUNGGO_DB_ENGINE="sqlite"; $env:DJANGO_DEBUG="True"; $env:PADUNGGO_SQLITE_PATH="ci.sqlite3"
.\.venv\Scripts\python.exe manage.py makemigrations --check --dry-run
Remove-Item Env:PADUNGGO_DB_ENGINE, Env:DJANGO_DEBUG, Env:PADUNGGO_SQLITE_PATH
```

Imported GTFS routes are `documented`. Set `PLANNER_ALLOW_DOCUMENTED=True` in
`.env` to include them in local results, as production does.

Generate a secret key: `python -c "import secrets; print(secrets.token_urlsafe(50))"`

Local PostGIS mode on Windows requires a GDAL install (OSGeo4W). Lite mode
does not require GDAL. Production migrations run from the Docker container
on Render (see below).

## Endpoints

`GET /health`, `GET /api/v1/health`, `GET /api/v1/locations`, `GET /api/v1/routes`,
`GET /api/v1/routes/{id}`, `POST /api/v1/journeys/plan`. Contract: [docs/API_DESIGN.md](../docs/API_DESIGN.md).

## Deploy to Render (free, Docker)

The Blueprint is `render.yaml` at the repo root (Singapore region, free plan).

1. Supabase: **Database → Extensions → enable `postgis`** (only that one).
2. Render Dashboard → **New → Blueprint** → choose the `PadungGo` repo and the
   branch to deploy.
3. When asked, paste `DATABASE_URL` (Supabase **Session pooler** URI with your
   real password). Leave `FRONTEND_ORIGIN` blank until the Vercel site exists.
   `DJANGO_SECRET_KEY` is generated by Render automatically.
4. Deploy. Migrations run automatically when the container starts.
5. Check `https://<service>.onrender.com/health`.
6. Admin user (the free plan has no shell): add `DJANGO_SUPERUSER_USERNAME`,
   `DJANGO_SUPERUSER_EMAIL`, `DJANGO_SUPERUSER_PASSWORD` under Environment,
   redeploy once, then delete those three variables.
   - If an account with that username already exists, it is **left unchanged**: a restart never overwrites its password.
   - **Forgotten password:** also set `DJANGO_SUPERUSER_RESET_PASSWORD=True`, redeploy once, log in, then delete all four variables.

GTFS upload limits (optional overrides):
- `GTFS_UPLOAD_MAX_MB`: compressed upload size, default 50.
- `GTFS_MAX_UNCOMPRESSED_MB`: total size once unzipped, default 500.

Oversized uploads are refused before the body is read.

HSTS (production only) is sent on HTTPS responses, starting at
`max-age=300` (5 minutes). Raise `DJANGO_SECURE_HSTS_SECONDS` step by step,
for example 86400 (1 day), then 604800 (1 week), then 31536000 (1 year),
only while HTTPS stays healthy. `includeSubDomains` and `preload` are
deliberately off. As a result, `check --deploy` still shows the two
intentional warnings W005 and W021.

Tests use `config/test_settings.py`, selected in `pytest.ini`. Production
security settings depend only on `DJANGO_DEBUG`.

Free-plan limits: the service sleeps after 15 minutes idle and takes about a
minute to wake up.

The AI explanation variables (`AI_BASE_URL`, `AI_API_KEY`, `AI_MODEL` and the
optional limits) are described in `.env.example` and in
[docs/API_DESIGN.md](../docs/API_DESIGN.md#explain-this-trip-ai-explanation).
The code lives in `transit/ai/`; the endpoint is `transit/api/explain_views.py`.
